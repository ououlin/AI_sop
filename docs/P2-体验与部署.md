> [文档索引](README.md)　·　上一阶段：[P1 核心功能增强](P1-核心功能增强.md)　·　下一阶段：[P3 商业化与规模化](P3-商业化与规模化.md)

## 1. 目标

解决试点评估暴露的三个硬伤：只靠手势判定误判高、异常没有闭环、单工位架构撑不起产线。

## 2. 背景与问题

| 问题 | 实际影响 |
|------|----------|
| 只有「手势 + 区域」二元判定 | 手部遮挡即失效，拿取/放置难区分 |
| 状态机只有三态 | 跳过、超时、顺序错误无法表达，更无法告警 |
| 单进程单摄像头 | 一个工位一套系统，产线级无全局视图 |
| 无权限控制 | 操作员与管理员权限不分 |
| 记录无法导出 | 无法对接工厂质量体系与 MES |

## 3. 交付内容

### 3.1 物体检测融合

- **方案**：YOLOv8 检测关键物体，步骤条件升级为「手 + 目标物体同时在目标区域」；未安装 `ultralytics` 时自动降级为颜色追踪
- **业务类别映射**：`config.OBJECT_CLASS_ALIASES` 把业务名（如 `circuit_board`）映射到模型输出类名，无需训练自定义模型即可表达业务语义
- **落地**：`backend/detectors/object_detector.py`、`backend/models.py`（`ObjectDetection`）、`backend/step_recognizer.py`
- **权重**：`yolov8n.pt` 不入库，缺失时自动降级

### 3.2 异常告警闭环

- **方案**：状态机扩展为 7 态（`pending / in_progress / completed / skipped / error / timeout / unauthorized_skip`）；`AlarmManager` 统一管理告警生命周期，支持超时、物体缺失、顺序异常
- **通知渠道**：日志 / Webhook / 声音，跨线程安全派发到事件循环
- **落地**：`backend/alarm/alarm_manager.py`、`backend/alarm/notifiers.py`、`backend/api/v1/reports.py`（`/reports/alarms` 系列接口）
- **结果**：告警可查询、可确认、可清空；新一次执行开始时自动重置

### 3.3 多工位架构与产线看板

- **方案**：工位 Agent 定时上报 → 中央聚合服务汇总 → 产线看板展示；单机部署时聚合路由内嵌在同一进程
- **安全**：工位上报使用 `X-Station-Key` 校验 `STATION_API_KEY`，与登录鉴权分离
- **落地**：`backend/agent/station_reporter.py`、`backend/central/aggregation_server.py`、`frontend/src/components/LineDashboard.tsx`
- **接口**：`POST /station/report`、`GET /stations`、`GET /stations/{id}`、`DELETE /stations/{id}`、`GET /line/summary`
- **部署开关**：`ENABLE_LOCAL_AGGREGATION` 控制是否挂载聚合路由；自调用时自动跳过上报，避免 httpx 回环

### 3.4 权限系统（JWT + RBAC）

- **方案**：JWT 登录，三角色权限矩阵：操作员（执行/查看本工位）、线长（看板/告警/导出/跳步）、管理员（SOP/摄像头/用户/告警管理）
- **落地**：`backend/auth/jwt_handler.py`（bcrypt 哈希）、`backend/auth/role_checker.py`、`backend/auth/dependencies.py`（`require_permission`）、`backend/middleware/auth_middleware.py`、`backend/api/v1/auth.py`、`frontend/src/components/Login.tsx`、`frontend/src/hooks/useAuth.ts`
- **结果**：所有业务接口按权限点校验；后续补了 HttpOnly Cookie 登录态

### 3.5 质检报告导出

- **方案**：从执行状态生成报告，支持 JSON / 文本 / CSV / PDF / Excel
- **落地**：`backend/reports/report_generator.py`、`pdf_renderer.py`、`excel_renderer.py`、`backend/api/v1/reports.py`、`frontend/src/components/ReportExport.tsx`
- **降级**：未安装 `reportlab` / `openpyxl` 时对应格式返回 503，不影响其它格式

## 4. 验收结果

功能项（已验证）：

- [x] 物体检测可启用，缺失模型时自动降级
- [x] 步骤超时 / 顺序异常触发告警，支持多渠道通知
- [x] 多工位上报与产线聚合接口联通
- [x] 三角色权限矩阵生效，越权返回 403
- [x] 四类报告格式可导出

指标项（待真实产线复验）：

- [ ] 步骤误判率 ≤ 5%（需产线视频实测）
- [ ] 物体检测准确率 ≥ 90%
- [ ] 30 工位并发上报压测
- [ ] 告警推送到达率（企业微信/钉钉）

## 5. 遗留与后续

- 精度指标缺少正式的现场基准数据，是 P3 试点要补的第一块
- 告警没有独立前端面板，当前通过操作面板与报告页呈现
- 报告只有手动导出，日报/周报定时任务未实现（P3 BI 阶段）
- 产线看板与工位前端同仓同构建，未拆分独立应用
- 所有数据仍是单租户结构（P3-M1 解决）
