## 4. 文档规范

每篇阶段文档遵循下列结构：

1. **目标** — 这一阶段要解决什么，一句话说清
2. **背景与问题** — 为什么现在做，问题带来的实际影响
3. **交付内容** — 按任务编号展开：问题 / 方案 / 落地文件 / 结果
4. **验收结果** — 已通过项与待现场验证项分开列
5. **遗留与后续** — 没做完的、降级处理的、指向下一阶段
6. **依赖与配置变更** — 新增依赖、环境变量

撰写约定：

- 状态标记统一用 ✅ 已完成 / 🚧 进行中 / 📋 规划中
- 文件路径一律写仓库相对路径（如 `backend/pipeline.py`），不写本机绝对路径
- 不粘贴与代码重复的大段实现，只写设计要点和文件指针；代码以仓库为准
- 已完成事项用 `[x]`，未完成用 `[ ]`，待现场复验的单独标注
- 新增阶段时，先在本索引登记，再写正文
