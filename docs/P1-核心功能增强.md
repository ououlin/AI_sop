# P1 · 核心功能增强

> **状态**：✅ 已完成　|　**周期**：2026-07　|　**目标**：提升核心功能可靠性与扩展性
>
> [文档索引](README.md)　·　上一阶段：[P0 稳定性与工程化](P0-稳定性与工程化.md)　·　下一阶段：[P2 识别精度与生产化](P2-体验与部署.md)

## 1. 目标

让系统从「单机演示」变成「可配置、可追溯的产品雏形」：SOP 能存能改、执行过程可回放、视频更省带宽、摄像头可热切换。

## 2. 背景与问题

| 问题 | 实际影响 |
|------|----------|
| SOP 只存 JSON 文件 | 现场改一条工序要手工编辑文件并重启 |
| 执行记录只存在内存 | 服务重启即丢，无法追溯 |
| 视频走 WebSocket base64 | 带宽占用高、首帧慢 |
| 换摄像头要改配置重启 | 产线调整成本高 |

## 3. 交付内容

### 3.1 数据库集成（SQLite + SQLAlchemy）

- **问题**：SOP 与执行记录无持久化
- **方案**：SQLite 零依赖落库，SQLAlchemy ORM 建模，Repository 层隔离 SQL
- **落地**：
  - `backend/database.py`（引擎、会话、`get_db`）
  - `backend/db_models.py`（`sop_definitions` / `execution_records` / `step_records`）
  - `backend/repositories/sop_repo.py`、`backend/repositories/record_repo.py`
  - `backend/api/v1/records.py`
- **结果**：SOP 与执行记录可持久化，重启不丢数据

### 3.2 MJPEG 视频流

- **问题**：WebSocket 传输 base64 帧，带宽翻倍
- **方案**：新增 MJPEG 端点，浏览器原生播放；WebSocket 保留给骨架标注流与状态推送
- **落地**：`backend/api/v1/video.py`（`/video/mjpeg`、`/video/snapshot`）
- **结果**：前端可二选一，带宽下降约 50%

### 3.3 SOP 可视化编辑器

- **问题**：手工写 JSON 易错
- **方案**：前端表格化编辑步骤，保存时写入数据库并可立即激活
- **落地**：`frontend/src/components/SopEditor.tsx`、`StepEditor.tsx`、`SopSwitcher.tsx`；后端 `/api/v1/sop/db/save`
- **结果**：工程师可自助配置工序，无需改文件

### 3.4 执行记录查询

- **问题**：无法查看历史执行
- **方案**：分页 + 条件筛选（时间范围 / 状态 / SOP 名称），提供记录详情
- **落地**：`backend/api/v1/records.py`、`backend/repositories/record_repo.py`、`frontend/src/components/RecordList.tsx`
- **结果**：`GET /api/v1/records`、`GET /api/v1/records/{id}`

### 3.5 摄像头运行时切换

- **问题**：换摄像头必须重启
- **方案**：列出可用设备 + 运行时切换
- **落地**：`backend/api/v1/camera.py`（`/camera/list`、`/camera/switch`）、`frontend/src/components/CameraSelector.tsx`
- **结果**：产线调整无需停服
