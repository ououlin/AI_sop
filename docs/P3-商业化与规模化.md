> **状态**：🚧 进行中　|　**周期**：2026-11 ~　|　**目标**：把单点项目验证转化为可复制的商业产品
>
> [文档索引](README.md)　·　上一阶段：[P2 识别精度与生产化](P2-体验与部署.md)　·　子计划：[P3-M1 SaaS 多租户](P3-M1-多租户实施计划.md)

## 1. 目标

P2 解决的是「能不能用」，P3 解决的是「能不能卖、能不能规模化交付」：多租户、可复制的工序模板、远程运维、数据增值与对外集成。

## 2. 背景与问题

| 问题 | 实际影响 |
|------|----------|
| 只能单租户本地部署 | 一个客户一套系统，运维成本高、客单价低 |
| 新行业从零配 SOP | 交付周期长，边际成本高 |
| 设备散落现场 | 健康度、算法版本、故障排查全靠人跑 |
| 数据只记录不分析 | 无法向管理者证明价值 |
| 封闭系统 | 接不进 MES/ERP，被当成试点而非常态 |

### 4.3 设备管理与远程运维（v1 已交付）

- **落地**：
  - `backend/ops/health_monitor.py`：按心跳 / 摄像头 / 帧率 / 延迟给出 healthy / warning / offline
  - `backend/ops/device_manager.py`：配置下发与升级命令队列（含回执）
  - `backend/ops/ota_updater.py`：模型版本目录（stable / candidate / fallback）
  - `backend/api/v1/ops.py`：设备列表、详情、配置下发、升级、命令历史、版本目录
  - `backend/agent/station_reporter.py`：上报版本与健康指标，心跳取命令并回执，配置可热应用
  - `frontend/src/components/DeviceManagement.tsx`：设备健康表、远程操作面板
- **v1 边界**：设备与控制面状态保存在内存（随服务重启清空）；升级只登记目标版本并回执，真正替换权重需重启工位进程；远程诊断仅到告警与命令记录，未做日志拉取与视频回放

### 4.4 数据分析与 BI 报表（v1 已交付）

- **落地**：
  - `backend/analytics/metrics_calculator.py`：OEE / FPY / CT / DPMO / MTBF 汇总
  - `backend/analytics/trend_analyzer.py`：每日趋势、瓶颈步骤、SOP 维度对比
  - `backend/api/v1/analytics.py`：`/analytics/overview|trend|steps|sops`
  - `frontend/src/components/Analytics.tsx`、`charts/TrendChart.tsx`：指标卡、SVG 趋势图、瓶颈与 SOP 表
- **v1 口径**（无标准工时数据时的近似）：
  - FPY = completed 执行数 / 总执行数
  - CT = 已完成执行的平均时长
  - OEE = 可用率（窗口内执行覆盖时长 / 窗口时长）× 表现指数（最快节拍 / 平均节拍）× 质量指数（FPY）
  - DPMO = 异常步骤数 × 1e6 / (步骤机会数 × 执行次数)
  - MTBF = 覆盖时长 / 失败执行次数
- **v1 边界**：没有班次、订单、人员维度，也没有标准工时基线，OEE 为近似值；车间大屏与人员效能分析未做

### 4.5 开放平台与生态（v1 已交付）

- **落地**：
  - `backend/openplatform/api_gateway.py`：API Key（SHA-256 摘要存储、read/write 作用域、吊销）
  - `backend/openplatform/webhook_manager.py`：订阅管理 + 事件投递（线程内异步、3 秒超时、投递日志）
  - `backend/openplatform/adapters/mes_adapter.py`：执行记录 → MES 通用报文
  - `backend/api/v1/openplatform.py`：`/api-keys`、`/webhooks` 管理端 + `/open/*` 开放端
  - `sdk/python/`：零依赖 Python 客户端
  - `docs/open-api.md`：接入指南
- **事件**：`execution.started`、`execution.completed`、`execution.failed`；`alarm.triggered` 已登记但未接入投递
- **v1 边界**：Webhook 已支持 HMAC 签名与失败重试；无按 Key 的限流；SDK 仅 Python；开发者沙箱未做

## 7. 验收标准

- [ ] 支持 10+ 租户同时运行，数据完全隔离
- [ ] 算法市场提供 20+ 预置工序模板（当前 6 个）
- [ ] 支持 OTA 算法热更新，更新过程不停机
- [ ] BI 报表支持 OEE / FPY / CT 等核心指标
- [ ] 开放 API 通过开发者沙箱自助测试
- [ ] 完成 1 家主流 MES 系统对接验证

## 8. 风险与对策

| 风险 | 对策 |
|------|------|
| 多租户改造成本被低估 | 先做行级隔离打通链路，schema 级隔离留作部署选项；阶段 0 已完成数据层地基 |
| 行业模板不足导致交付仍靠定制 | 优先沉淀 2-3 个高频行业模板，其余按项目抽象 |
| 现场设备运维吃掉利润 | 与 4.3 合并排期，先把健康监控做薄做对 |
