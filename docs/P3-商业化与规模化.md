# P3 · 商业化与规模化

> **状态**：🚧 进行中　|　**周期**：2026-11 ~　|　**目标**：把单点项目验证转化为可复制的商业产品
>
> [文档索引](README.md)　·　上一阶段：[P2 识别精度与生产化](P2-体验与部署.md)　·　子计划：[P3-M1 SaaS 多租户](P3-M1-多租户实施计划.md)

## 1. 目标

P2 解决的是「能不能用」，P3 解决的是「能不能卖、能不能规模化交付」：多租户、可复制的工序模板、远程运维、数据增值与对外集成。

## 2. 背景与问题

| 问题 | 实际影响 |
|------|----------|
| 只能单租户本地部署 | 一个客户一套系统，运维成本高、客单价低 |
| 新行业从零配 SOP | 交付周期长，边际成本高 |
| 设备散落现场 | 健康度、算法版本、故障排查全靠人跑 |
| 数据只记录不分析 | 无法向管理者证明价值 |
| 封闭系统 | 接不进 MES/ERP，被当成试点而非常态 |

## 4. 任务详情

### 4.1 SaaS 多租户平台（进行中）

- **方案**：租户数据隔离 + 订阅制计费 + 自助开通。**先做数据面多租户**，识别流水线仍按工位独立部署
- **落地**：`backend/saas/`、`backend/middleware/tenant_middleware.py`、`backend/api/v1/tenant.py`、`frontend/src/pages/admin/TenantManagement.tsx`
- **详细计划**：[P3-M1-多租户实施计划.md](P3-M1-多租户实施计划.md)（阶段 0 已完成）

**订阅套餐设计**：

| 套餐 | 价格 | 工位数 | 数据保留 | 功能 |
|------|------|--------|----------|------|
| 体验版 | 免费 | 1 | 7 天 | 基础识别 |
| 标准版 | 999/月 | 5 | 30 天 | +告警+报告 |
| 专业版 | 2999/月 | 20 | 1 年 | +多工位看板 |
| 企业版 | 定制 | 不限 | 不限 | +私有部署+定制 |

### 4.2 算法市场与工序模板

- **方案**：预置行业工序模板，一键应用并按摄像头视角自适应；社区可贡献检测模型
- **落地**：`backend/marketplace/template_registry.py`、`model_registry.py`、`backend/api/v1/marketplace.py`、`frontend/src/pages/TemplateLibrary.tsx`
- **模板库**：电子装配（PCB 贴片/插件焊接/成品测试）、汽车零部件（螺栓拧紧/零件装配/质检）、食品包装（灌装/封口/贴标）、医疗器械（灭菌包装/装配检验）

### 4.3 设备管理与远程运维

- **方案**：工位 Agent 集中纳管、OTA 算法热更新、健康监控（摄像头/网络/算法服务）、远程诊断（日志/回放/配置下发）
- **落地**：`backend/ops/device_manager.py`、`ota_updater.py`、`health_monitor.py`、`backend/api/v1/ops.py`、`frontend/src/pages/admin/DeviceManagement.tsx`

### 4.4 数据分析与 BI 报表

- **方案**：效率（OEE/CT/瓶颈）、质量（合格率趋势/异常分布）、人员效能三类分析，配合车间大屏
- **落地**：`backend/analytics/metrics_calculator.py`、`trend_analyzer.py`、`backend/api/v1/analytics.py`、`frontend/src/pages/Analytics.tsx`
- **核心指标**：OEE（可用率×表现指数×质量指数）、FPY（一次通过率）、CT（节拍时间）、DPMO（百万机会缺陷数）、MTBF（平均故障间隔）

### 4.5 开放平台与生态

- **方案**：开放 REST API + Webhook 事件订阅，预置 MES/ERP 适配器，提供 Python/Java/JS SDK
- **落地**：`backend/openplatform/api_gateway.py`、`webhook_manager.py`、`openplatform/adapters/`、`sdk/`、`docs/api/`
- **事件**：`execution.started`、`execution.completed`、`step.completed`、`alarm.triggered`、`station.offline`

## 7. 验收标准

- [ ] 支持 10+ 租户同时运行，数据完全隔离
- [ ] 算法市场提供 20+ 预置工序模板
- [ ] 支持 OTA 算法热更新，更新过程不停机
- [ ] BI 报表支持 OEE / FPY / CT 等核心指标
- [ ] 开放 API 通过开发者沙箱自助测试
- [ ] 完成 1 家主流 MES 系统对接验证

## 8. 风险与对策

| 风险 | 对策 |
|------|------|
| 多租户改造成本被低估 | 先做行级隔离打通链路，schema 级隔离留作部署选项；阶段 0 已完成数据层地基 |
| 行业模板不足导致交付仍靠定制 | 优先沉淀 2-3 个高频行业模板，其余按项目抽象 |
| 现场设备运维吃掉利润 | 与 4.3 合并排期，先把健康监控做薄做对 |
