>
> [文档索引](README.md)　·　下一阶段：[P1 核心功能增强](P1-核心功能增强.md)

## 1. 目标

把「能跑起来的演示程序」改造成「可以无人值守运行的服务」：异常不崩溃、配置不硬编码、日志可追溯、接口可演进。

## 2. 背景与问题

| 问题 | 实际影响 |
|------|----------|
| 处理循环异常后只打一行日志 | 夜间无人值守时服务静默停摆，只能手动重启 |
| 配置硬编码在 Python 文件里 | 换部署环境要改代码，容易漏改 |
| 各接口错误响应格式不一致 | 前端无法统一处理错误 |
| API 没有版本前缀 | 后续迭代会直接破坏调用方 |
| 日志只输出到控制台 | 现场出问题无法回溯 |

## 3. 交付内容

### 3.1 全局异常处理

- **问题**：未捕获异常直接抛给 ASGI，前端收到非结构化响应
- **方案**：注册全局异常处理器，统一错误结构与日志
- **落地**：`backend/middleware/error_handler.py`、`backend/main.py`
- **结果**：未处理异常统一返回 `{"error": ..., "code": ...}`，并记录完整堆栈

### 3.2 处理循环守护

- **问题**：识别循环一崩，整个服务「还在跑但不出画面」
- **方案**：把处理循环从 `main.py` 拆成独立模块，异常后退避重启并记录
- **落地**：`backend/pipeline.py`（`ProcessingPipeline`）
- **结果**：主服务只负责装配与生命周期，循环异常可观测、可恢复

### 3.3 环境配置管理

- **问题**：端口、摄像头参数、日志级别全部写死在代码里
- **方案**：`python-dotenv` + 环境变量，集中到配置对象
- **落地**：`backend/config.py`、`backend/.env.example`
- **结果**：部署参数全部走 `.env`，模板文件随仓库分发

### 3.4 日志规范

- **问题**：日志格式不统一，无级别控制，不落盘
- **方案**：统一 formatter，控制台 + 文件双输出，文件按大小滚动
- **落地**：`backend/logging_config.py`、`backend/logs/`
- **结果**：`LOG_LEVEL` 可配，现场问题可回溯

### 3.5 API 版本化

- **问题**：裸路径接口，无法演进
- **方案**：统一 `/api/v1` 前缀，按领域拆分路由模块
- **落地**：`backend/api/v1/`（health / sop / camera / video / records / auth / reports）
- **结果**：路由模块化，新增 v2 时不必推翻现有调用方
